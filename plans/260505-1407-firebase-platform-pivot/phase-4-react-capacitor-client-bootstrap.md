## Overview

- Stand up Vite + React 18 + TS app at `web/`. Capacitor configured for Android first, iOS deferred. Firebase web SDK wired for Auth (Google, Email/Pass, Anonymous, `linkWithCredential`). WS client opens to `wss://api.dleague.tld/ws`, sends `AUTH_HELLO` first frame, decodes binary protobuf envelopes via protobuf-ts.

## Key Insights
- Vite output dir = `web/dist/` — Go server's `http.FileServer` (per `server/internal/http/router.go:51`) gets pointed to `dist/` in dev, but in prod the React app is served by Firebase Hosting (separate domain), Go server only serves `/ws` + `/health` from `api.dleague.tld`. Dev mode = Vite dev server with proxy to Go for `/ws`
- Capacitor wraps the Vite-built static SPA into a native shell; the WebView calls `wss://api.dleague.tld/ws` directly (no localhost in prod)
- `firebase/auth` JS SDK handles ID token refresh in background (every ~50min); we just call `getIdToken()` to grab fresh one before WS reconnect
- Anonymous → permanent: `linkWithCredential(currentUser, googleCredential)` keeps SAME UID; no data migration needed
- protobuf-ts is the maintained successor to protobufjs; smaller bundle, generates idiomatic TS types from .proto files
- Tailwind v4 (2026 ship): YAGNI. Plain CSS modules + a few utility classes is enough for grid + colors
- Workbox / PWA: defer to phase-8 (offline play not in MVP scope)

- File size: each `.tsx` <200 LOC

### Auth flow
```
[App] mount → onAuthStateChanged callback
  → user == null → show <LoginScreen>
  → user != null → connectWS()
                    → ws.open
                    → user.getIdToken(true)  // force refresh
                    → ws.send(envelope{type:AUTH_HELLO, payload:AuthHello{id_token}})
                    → await envelope{type:AUTH_ACK} (timeout 5s)
                    → mark connected; show <Home>
```

### Anonymous → permanent upgrade
```ts
// auth-flows.ts
async function linkAnonToGoogle(): Promise<UserCredential> {
  const cred = GoogleAuthProvider.credential(...);
  return linkWithCredential(auth.currentUser!, cred);
  // UID stays same; user.isAnonymous flips to false
}
```

UI: when `user.isAnonymous === true`, render `<UpgradePrompt/>` banner. After upgrade, banner disappears, all match history (keyed by UID) carries over for free.

### WS client state machine
```
DISCONNECTED ──(connect)──> CONNECTING ──(open)──> AUTHENTICATING ──(ACK)──> READY
       ↑                                                                       │
       └──────────────────────(close|error|token-expired)──────────────────────┘
```

## Implementation Steps
1. **Delete `client/` Go module:** `rm -rf client/`; remove from `go.work`; `cd server && go mod tidy`
2. **Delete old web shell:** `rm web/index.html web/styles.css web/wasm_exec.js web/main.wasm` (last may not exist)
3. **Bootstrap Vite + React + TS:**
   - `cd web && npm create vite@latest . -- --template react-ts`
   - `npm install`
4. **Install runtime deps:** `npm i firebase @protobuf-ts/runtime`
5. **Install dev deps:** `npm i -D @protobuf-ts/plugin @types/node @capacitor/core @capacitor/cli @capacitor/android`
6. **Codegen protobuf:** add Make target `proto-gen-ts` that calls `protoc --plugin=...protobuf-ts... --ts_out=web/src/pb proto/dleague/v1/*.proto`; commit generated TS files
7. **Configure `vite.config.ts`** with proxy:
   ```ts
   server: { proxy: { '/ws': { target: 'ws://localhost:8080', ws: true } } }
   ```
8. **Configure Firebase web SDK** in `firebase/client.ts`:
   ```ts
   const cfg = { apiKey: import.meta.env.VITE_FIREBASE_API_KEY, authDomain: ..., projectId: ... };
   export const app = initializeApp(cfg);
   export const auth = getAuth(app);
   ```
9. **Implement `auth-flows.ts`:**
   - `signInWithGoogleRedirect()` (or popup; popup easier dev)
   - `signInWithEmail(email, password)` + `createUserWithEmail`
   - `signInAnon()` returns user
   - `linkAnonToGoogle()` and `linkAnonToEmail(email, password)`
10. **Implement WS client:**
    - `WSClient` class wraps `WebSocket`; reconnect with exponential backoff (1s→30s cap)
    - On open: invoke `auth-handshake.ts` → wait AUTH_ACK
    - On close 4401: trigger token refresh + reconnect
11. **Implement `auth-handshake.ts`:**
    - `await user.getIdToken(true)` (force refresh)
    - Wrap in `AuthHello` proto, marshal envelope, send binary
    - Wait for `AUTH_ACK` (with 5s timeout); on `AUTH_ERROR` propagate to UI
12. **Implement React components:**
    - `<LoginScreen/>` with 3 buttons + email form
    - `<UpgradePrompt/>` shown only if `user.isAnonymous`
    - `<Header/>` shows display_name + sign-out
    - `<App/>` routes between login / home based on auth state
13. **Capacitor scaffold:** `npx cap init dleague tld.dleague.app`; `npx cap add android` (defer iOS)
14. **Capacitor build verify:** `npm run build && npx cap sync && npx cap open android` (only if Android Studio available; if not, defer to phase-8)
15. **Update Makefile:**
    - `dev:` runs `cd server && go run ./cmd/api` AND `cd web && npm run dev` in parallel (use `&` or `make -j`)
    - `build-web:` runs `cd web && npm run build`
    - Remove `build-wasm`, `build-wasm-debug`, `$(WASM_EXEC_DST)`
16. **Smoke test locally:**
    - `make dev` → open `http://localhost:5173`
    - Click "Play as guest" → anonymous sign-in → WS connects → AUTH_ACK received
    - Refresh: still authed (Firebase persists IndexedDB)
    - Click "Sign in with Google" → linkWithCredential → upgrades to permanent

## Risk Assessment
| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| protobuf-ts codegen flakiness vs. protobufjs ecosystem | Med | Med | Have fallback `protobufjs` recipe in NEXT_STEPS; <1d swap if needed |
| Firebase modular SDK still ships full 80 KB even with tree-shake | Low | Low | Acceptable per bundle target; verify via `vite build --report` |
| Vite proxy fails to upgrade WS in dev | Med | Med | Document `proxy.ws=true`; fallback: hardcode `ws://localhost:8080/ws` in `.env.local` |
| Anon-link race: user signs in with Google in another tab | Low | Med | Firebase SDK handles via `onAuthStateChanged`; UI shows error toast on link conflict |
| Capacitor Android build needs Java 17 + Android SDK | High | Med | Phase-8 owns; if blocked, web-only ship still acceptable per locked decisions |
| Firebase config has API key visible in client bundle | Cert | Low | This is BY DESIGN — Firebase web config is public; security enforced via rules + auth, not config secrecy |
| Strict mode catches protobuf-ts emitting `any` types | Low | Low | Type assertions at boundary; rare |
| Token refresh races with WS handshake | Med | Med | `getIdToken(true)` resolves fresh token; SDK handles serialization |

## Security Considerations
- Firebase web config (`apiKey`, `authDomain`) IS public; visible in bundled JS. Security comes from Firestore Rules + Auth, NOT config opacity. Document this in code comment to prevent future "secret leak" panic
- Never store ID tokens in localStorage manually — Firebase SDK persists in IndexedDB with refresh-token rotation built in
- WSS only in prod (Hosting → backend); WS allowed in dev (localhost only)
- Email/password: enforce min 8 chars (Firebase has built-in min, but UI validates pre-submit)
- Google sign-in popup may be blocked by browsers; fallback to redirect flow on retry
- CSRF: Firebase Auth flows use OAuth state param internally; we don't need cookies for auth
