# Dleague Pivot: Svelte + Phaser + Firebase + MongoDB

## Goal
Pivot Dleague off Ebitengine/WASM + MySQL HeatWave + cookie-sessions to Svelte+Phaser + MongoDB Atlas + Firebase Auth. Keep Go server, single-WS architecture, protobuf wire format. Ship daily / async / sync PvP on the new stack.

## Stack (HARD)
| Layer  | Tech                                                                |
|--------|---------------------------------------------------------------------|
| Server | Go (chi + `coder/websocket` + `mongo-driver/v2` + `firebase-go/v4`) |
| Client | SvelteKit (adapter-static) + Phaser 3.80+ + `@bufbuild/protobuf-es` |
| Auth   | Firebase Auth (Email/Pw + Google + Anonymous); ID-token over WS     |
| DB     | MongoDB Atlas M0 free tier; lazy schema-version migration            |
| Wire   | Binary protobuf over single WebSocket; debug-tag protojson logging  |
| Deploy | Fly.io for Go server; Go serves `web/dist/` static                  |

## Surviving Phase 1 (kept intact, hardened in phase 02-03)
- `server/cmd/server/main.go` (boot wiring)
- `server/internal/config/config.go` (extend env vars; same shape)
- `server/internal/http/{router.go,health.go}` (security headers + auth gate added)
- `server/internal/ws/{conn.go,hub.go,ping.go,debug_log.go,debug_log_noop.go}` (refactored, not rewritten)
- `proto/dleague/v1/envelope.proto` + `shared/pb/...` (extended; envelope unchanged)
- `shared/game/{game.go,registry.go}` (interface generalized)
- `Makefile`, `buf.gen.yaml`, `.golangci.yml`, `go.work`

## Being deleted
- `client/` (entire Ebitengine module: cmd/, internal/, go.mod, go.sum)
- `web/wasm_exec.js`, `web/index.html` (regenerated by SvelteKit)
- `server/internal/store/{store.go,migrate.go,users.go}` (MySQL driver + migrations)
- `server/internal/store/migrations/` (SQL files)
- `docker-compose.yml` Postgres service (replaced by `mongo:7` + `mongo-express`)

## Key Decisions
| # | Decision                                          | Rationale                                                                                                                  |
|---|---------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------|
| 1 | Svelte over React                                 | ~2-3 KB runtime vs ~40 KB; compiler-eliminated. Faster TTI for -dle UI. (svelte-phaser report §1)                          |
| 2 | SvelteKit + adapter-static over plain Vite+Svelte | File-based routing, opinionated SPA fallback, single `web/dist/` for Go FileServer (svelte-phaser report §1)               |
| 3 | Phaser 3.80+ over PixiJS / canvas-from-scratch    | Official Svelte template, 110 KB gz, scene/eventbus pattern proven (svelte-phaser report §2)                               |
| 4 | `@bufbuild/protobuf-es` over `protobuf-ts`        | 15-20% bundle overhead vs 62%; 100% conformance; Buf-native gen alongside Go (svelte-phaser report §3)                      |
| 5 | MongoDB Atlas over Firestore                      | Free 512 MB + transactions on M0, idiomatic Go driver, lower lock-in than Firestore SDK (mongo report §2,5)                |
| 6 | Atlas M0 over Flex tier                           | $0/mo for MVP; Flex base is $8 + WPU costs that bite on attempt-heavy workload (mongo report §9)                           |
| 7 | Firebase Auth over self-hosted (Ory/SuperTokens)  | 50K MAU free, JS SDK trivial sign-in, Admin SDK Go is mature v4.19+ (firebase report §1, §8)                               |
| 8 | `Sec-WebSocket-Protocol: fb.<idtoken>` over post-upgrade auth msg | Token verified at HTTP upgrade — no message dispatch before auth, no DDoS surface (firebase report §2)              |
| 9 | `coder/websocket` over `nhooyr.io/websocket`      | nhooyr is archived (security-review L1); coder fork is API-compatible; one-line import path change                         |
| 10 | Lazy schema-version migration over SQL-style migrate | No downtime, no bulk ops, eventual consistency acceptable for MVP (mongo report §6)                                     |
| 11 | Concrete `GameState` proto over opaque `bytes State` | Type safety; resolves code-review L8 + open question on JSON-vs-proto serialization                                     |

## Open Risks
- **Atlas M0 auto-pause** after 30 days idle → 1-2 min cold start; mitigate with synthetic ping cron from CI nightly. (mongo report §2)
- **Firebase ID token 1h expiry** mid-match → client must refresh at 50min; server must accept `AuthRefresh`. (firebase report §4)
- **Phaser bundle creep** — full 110 KB gz baseline; if game library grows, custom build will be required. Defer until measurable. (svelte-phaser report §2)
- **Atlas IP allowlist vs Fly.io NAT** — Fly outbound IPs unstable → must use `0.0.0.0/0` until we move to M10 + VPC peering. (mongo report unresolved Q5)
- **WS slow client backpressure** — current Phase 1 has none; Phase 2 must add bounded `send` channel before any broadcast lands. (code-review H1+H2)
- **Firebase outage = auth broken** — no fallback identity provider; document as accepted risk. (firebase report §10)
- **SvelteKit prerender + WS auth** — initial page must not require token; auth happens client-side post-load. Ensure no SSR call needs auth.

## Success Criteria
- [ ] `make dev` boots Mongo + emulator + Go server + SvelteKit dev server cleanly
- [ ] User signs in via Email/Pw, Google, or Anonymous in browser
- [ ] WS upgrade rejects missing/invalid Firebase ID token (401)
- [ ] User plays full Wordle round offline in Phaser scene
- [ ] Daily puzzle: same date → same answer for all users
- [ ] Challenge link flow: A finishes → shares URL → B plays → both see correct winner
- [ ] Quick Match: queue → pair <2s → opponent progress (color squares only) <200ms p95
- [ ] Mongo round-trip <50ms p95 for index-backed lookups
- [ ] CI passes `go test -race` + lint + `buf lint` + `npm run build`
- [ ] Production deploy on Fly.io serves `/` from `web/dist/` and `/ws` upgraded
- [ ] Bundle size: Svelte+Phaser+protobuf <400 KB gzipped

## Out of Scope (v2+)
Native mobile (gomobile / Capacitor); custom-claims roles beyond admin; Redis pub-sub for multi-region matchmaking; Mongo Change Streams for live leaderboard; full-text search; backups (M0 lacks them); SMS auth; tournament brackets; spectator mode.
